# 설치 점검

1. 실행한다 (1~3분):

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/scripts/check.py" --listing
   ```

   윈도우에서 `python3` 가 안 되면 `python` 으로 바꿔 실행한다(이 경우 1번 항목은 ✗ 로 나온다).

2. 출력 표를 **그대로** 보고한다. △ 는 선택 항목이라 실패가 아니다.

3. ✗ 마다 원인·조치를 한 줄씩 붙인다.

   | ✗ 항목 | 조치 |
   |---|---|
   | python3 실행 | 윈도우 MS 스토어 스텁이거나 없음 → 설치 스크립트를 다시 돌리면 python3 별칭을 만든다 |
   | 작업 규칙 연결 | `workflow-rules.md` 또는 `CLAUDE.md` 의 `@workflow-rules.md` 줄이 없음 → 설치 스크립트 재실행 |
   | 플러그인 설치·활성 | 빠졌거나 꺼진 플러그인 → `/plugin` 에서 설치·켜기, 그래도 없으면 설치 스크립트 재실행 |
   | 로컬 스킬 | 빠진 스킬 → 설치 스크립트 재실행 |
   | 숨김·합침 유지 | 플러그인 업데이트로 풀림 → 설치 스크립트 재실행(또는 `trim-descriptions.py --all --apply`) |
   | 위험 명령 차단 훅 | 훅이 rm -rf 를 막지 못함 → 플러그인 재설치 후 다시 점검 |
   | 새 세션 스킬 목록 | 숨김 노출·대표 빠짐 → 숨김 재적용 후 Claude Code 재시작 |

4. **고치기 전에 사용자에게 무엇을 할지 알리고** 확인을 받는다. 점검 자체는 파일을 고치지 않는다 — 단 `--listing` 은 새 Claude 세션을 잠깐 띄워(haiku, 사용량 조금) 스킬 목록을 받는다. 빼고 돌리려면 `--listing` 없이 실행한다.
